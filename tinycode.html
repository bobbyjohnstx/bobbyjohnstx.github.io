Run Locally

tinycode

github.com/bobbyjohnstx/tinycode

The core application. Includes the TUI, web UI, desktop app, built-in agents, skills, and LLM provider integrations. Everything you need to run tinycode on your workstation.

Quick start

# Install and run (requires Bun)
$ bun install
$ bun dev

# Run against a specific project
$ bun dev /path/to/project

# Start the web UI
$ bun dev web
# → http://localhost:4096

Connect an LLM

tinycode auto-discovers Ollama on localhost:11434 and vLLM on localhost:8000 at startup.

# Point to a LAN model-as-a-service server
$ export TINYCODE_MAAS_HOST=https://your-maas-server
$ export TINYCODE_MAAS_API_KEY=your-key

# Or configure in ~/.config/tinycode/config.json
{ "model": "ollama/llama3.2" }

Interfaces

  • TUI — primary interface. Full interactive session in your terminal with conversation history, model switching, agents, and tool approval.
  • Web UI — SolidJS + TailwindCSS. Same capabilities in a browser at localhost:4096.
  • Desktop — Electron app for macOS, Windows, and Linux. Run bun run --cwd packages/desktop dev.

What's included

  • 20+ built-in agents — architect, debugger, code-reviewer, security-reviewer, planner, test-engineer, and more. Invoke with /ask <agent>.
  • Skills — slash commands for specialized tasks: /debug, /trace, /verify, /deepinit, /mcp-setup.
  • oh-my-tiny plugin — extended orchestration tools, notepad, wiki, project memory, and AST grep.
Run in a Container

tinycode-container

github.com/bobbyjohnstx/tinycode-container

Packages tinycode with oh-my-tiny, tmux, and git into a single OCI image. Built on UBI9-minimal, OpenShift-compatible with arbitrary UID support. Multi-arch (amd64 + arm64).

One-line install

$ curl -fsSL https://raw.githubusercontent.com/bjohns/tinycode-container/main/install.sh | sh

# Installs a `tinycode` wrapper that manages the container lifecycle.
# First run pulls the image; subsequent runs attach instantly.
# Uninstall: tinycode --uninstall

Or run directly with Podman / Docker

# Basic — Ollama on the host network
$ podman run -it --network host \
  -e TINYCODE_SERVER_PASSWORD=changeme \
  quay.io/bjohns/tinycode-container:latest

# With a remote vLLM endpoint
$ podman run -it -p 4096:4096 \
  -e TINYCODE_VLLM_URL=http://your-vllm-server:8000 \
  -e TINYCODE_SERVER_PASSWORD=changeme \
  quay.io/bjohns/tinycode-container:latest

# With persistent storage
$ podman run -d -p 4096:4096 \
  -v tinycode-data:/home/tinycode/.local/share/tinycode \
  -v tinycode-config:/home/tinycode/.config/tinycode \
  quay.io/bjohns/tinycode-container:latest

Deploy to OpenShift with Kustomize

# Base deployment (Deployment + Service + Route)
$ kubectl apply -k k8s/base

# Ephemeral (no PVC — testing only)
$ kubectl apply -k k8s/overlays/ephemeral

Features

  • GitOps mode — clone a repo on startup via TINYCODE_GIT_REPO with optional auto-pull on restart.
  • vLLM auto-config — set TINYCODE_VLLM_URL to auto-configure endpoint and model.
  • Cluster-admin mode — TINYCODE_CLUSTER_ADMIN=true downloads oc CLI for cluster management.
  • Swarm tool — includes tmux for supervised multi-worker sessions with shared persistence.
Deploy on OpenShift

tinycode-operator

github.com/bobbyjohnstx/tinycode-operator

A Kubernetes Operator for OpenShift that manages TinycodeInstance custom resources. Handles deployment, PVC provisioning, Route creation, SCC binding, and vLLM auto-probing. Reduces a full deployment to a single CR.

Install the operator

$ git clone https://github.com/bobbyjohnstx/tinycode-operator
$ cd tinycode-operator

# Build and push the operator image
$ make push IMAGE_ORG=yourorg IMAGE_TAG=v0.1.0

# Install on the cluster (cluster-admin required)
$ make install OPERATOR_IMAGE=quay.io/yourorg/operator:v0.1.0

Create a TinycodeInstance

# Create namespace and password secret
$ oc new-project tinycode-dev
$ oc create secret generic tinycode-password \
  --from-literal=TINYCODE_SERVER_PASSWORD=mysecretpass

# Apply the CR
$ oc apply -f - <<EOF
apiVersion: tinycode.dev/v1alpha1
kind: TinycodeInstance
metadata:
  name: my-tinycode
spec:
  vllm:
    - name: vllm-qwen3
      url: http://qwen3-30b.qwen3.svc.cluster.local:8080
  model: "vllm-qwen3/qwen3-30b"
  auth:
    passwordSecret: tinycode-password
  storage:
    projectsSize: "20Gi"
# Check status
$ oc get tinycodeinstances
NAME          READY   URL                                       AGE
my-tinycode   True    https://my-tinycode-tinycode-dev...        5m

Security contexts

The operator installs three SCCs, applied automatically based on the CR spec.

  • tinycode-restricted — default. Non-root (UID 1001), all capabilities dropped.
  • tinycode-hostpath — when spec.storage.hostPath is set. Adds hostPath mount, requires cluster-admin approval.
  • tinycode-shell — when spec.shell.enabled: true. Adds hostPID + SYS_PTRACE for host shell access. Requires review.
Ecosystem

Three projects, one stack

tinycode is designed as a layered system. Use whichever level fits your environment.

tinycode
Core server, TUI, web UI, desktop app, agents, skills, tools, and LLM provider integrations.
tinycode-container
OCI container image. UBI9-minimal, multi-arch, OpenShift arbitrary-UID compatible. Adds GitOps, vLLM auto-config, cluster-admin mode.
tinycode-operator
Kubernetes Operator for OpenShift. Manages TinycodeInstance CRs with Helm-based reconciliation, SCCs, Routes, PVCs, and vLLM auto-probing.
